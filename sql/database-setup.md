# Database Setup

This repository ships with a unified Postgres schema for Stroop tests, chat interactions, and prompt-quality analytics.  
The schema lives in `sql/database-setup.sql` and replaces earlier one-off migration files.  
Use this guide to provision a new database or upgrade an existing one.

## Prerequisites

- PostgreSQL 14+ (the schema uses `INET`, `JSONB`, and generated columns).  
- A Postgres role with privileges to create tables, indexes, and comments.  
- Access to the `psql` CLI or another SQL execution tool.

## Creating A Fresh Database

1. Create an empty database (skip if one already exists):
   ```bash
   createdb next_pup
   ```
2. Load the schema:
   ```bash
   psql -d next_pup -f sql/database-setup.sql
   ```
   The script is idempotent — all objects are created with `IF NOT EXISTS`, so re-running it is safe.

## Upgrading An Existing Database

The merged `database-setup.sql` now contains:

- Core tables (`users`, `user_sessions`, `stroop_trials`, `chat_interactions`).
- Readability metrics, structural-quality scores, OpenAI usage metadata, and aggregated session statistics.
- Supporting indexes and column-level documentation.

To bring an older database up to date, run the sections you need or execute the whole file:
```bash
psql -d <your_db> -f sql/database-setup.sql
```
Because every `ALTER TABLE` call uses `ADD COLUMN IF NOT EXISTS`, executing the file repeatedly will not drop or overwrite data.

### Optional: Verify Schema Parity

You can confirm that the critical tables have the expected columns with:
```sql
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'chat_interactions'
ORDER BY column_name;
```

## Table Highlights

- `users`: Stores participant identity (email, username, six-digit passcode).  
- `user_sessions`: Tracks routing/source metadata, Stroop state, final submissions, and aggregated structural scores.  
- `stroop_trials`: Trial-by-trial Stroop responses with timing and accuracy.  
- `chat_interactions`: Full prompt/response transcript with readability metrics, structural quality annotations, OpenAI billing stats, and latency data.

## Index Coverage

The setup script creates indexes for common access patterns, including:

- `users`: lookups by `user_id`, `email`, `username`, and `passcode`.  
- `user_sessions`: filters by `user_id` and `session_id`.  
- `stroop_trials`: filters by `user_id` or `session_id`.  
- `chat_interactions`: scenario filters, task codes, structural-quality scores, readability metrics, latency columns, and timestamps.

These indexes align with the analytics queries generated by the application.

## Column Documentation

For reference, the script contains `COMMENT ON COLUMN` statements for every chat interaction field and all aggregated session metrics.  
This metadata is visible in `psql` via `\d+ chat_interactions` and helps analysts understand the semantic meaning of each value.

## When To Re-run The Script

- After pulling schema updates from git.  
- When provisioning staging/production environments.  
- Following a restore from backup if the schema pre-dates the consolidated migrations.

If you need historical migrations for auditing, check git history prior to the merge where individual `migration-add-*.sql` files existed.

## Troubleshooting

- **Permission errors**: ensure your Postgres role has privileges to create tables, indexes, and comments.  
- **Conflicting constraints**: the script drops and recreates check constraints where necessary (e.g., scenario values). If you added custom constraints, review before re-running.  
- **Performance tuning**: feel free to comment out indexes you do not need, but keep the readability/structural metrics indexed if you rely on analytics dashboards.

Need a lighter-weight subset for local analytics? Copy `sql/database-setup.sql`, remove unused sections, and apply the trimmed script to a scratch database.
